# Security policy

## Supported versions

Only the latest version published to npm gets security fixes.

## Reporting a vulnerability

Please don't open a public issue, discussion or PR for a vulnerability.

Report it privately through GitHub: go to the repository's **Security** tab and click **Report a vulnerability**. Only the maintainer can see the report.

Include, if you can:

- what is affected (a component, the CLI, the template, a file);
- the steps to reproduce it;
- what an attacker could do with it.

## What to expect

- An answer within 5 business days.
- Updates while the fix is in progress.
- Credit in the advisory once the fix is released, if you want it.

## Scope

In scope: the code in this repository, the npm package and the project the CLI creates from `template/`.

Out of scope: vulnerabilities in third-party dependencies with no impact on Kami (report those to their owners), denial of service, and social engineering.
